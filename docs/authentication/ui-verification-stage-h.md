## Findings

| # | Area | Result | File / location | Detail / fix |
|---|---|---|---|---|
| H1 | OTP error association | **Issue — fixed in staging** | `email-verification-form.tsx`, code-phase error `<p>` and recovery-phase error `<p>`; the six digit inputs and the recovery email input | Each digit input had `aria-invalid` but no `aria-describedby`, and the error `<p role="alert">` had no `id`, so a screen reader announced the error text but did not associate it with the field that failed. **Fix (staged in this delivery):** both error paragraphs get `id="cm-verify-error"` (only one phase renders at a time, so the id is never duplicated in the DOM) and the inputs get `aria-describedby={error ? "cm-verify-error" : undefined}`. No visual or behavioural change. |
| H2 | Labels on all auth fields | PASS | `access-form.tsx` (`field()` helper), `email-actions.tsx`, `email-verification-form.tsx` recovery input, `account-dashboard.tsx` `ProfileActions` | Every input is wrapped by its `<label>` (implicit association). No orphan inputs. |
| H3 | Field-error association (sign-in/up/recovery) | PASS | `access-form.tsx` | Each field sets `aria-invalid` + `aria-describedby="access-<field>-error"` pointing at the `<span id="access-<field>-error" class="cm-field-error">`; on submit with errors the first invalid field is focused programmatically. A visually-hidden `<p role="alert">` summarises the failure. |
| H4 | OTP keyboard behaviour | PASS | `email-verification-form.tsx` | Six boxes: `inputMode="numeric"`, `pattern="[0-9]*"`, `maxLength={1}`, `autoComplete="one-time-code"` on the first box; Backspace moves back and clears, ArrowLeft/Right move focus, paste fills boxes in order, focus auto-advances, `onFocus` selects the box content. Auto-submit on the 6th digit, guarded against double-submit and against re-submitting a failed code (documented `submittedCodeRef` guard). |
| H5 | Loading states | PASS | `access-form.tsx` (`pending` → "Please wait…", inputs + submit disabled), `email-verification-form.tsx` (loading phase `role="status"` "Checking your verification…"; verify → "Verifying…"; resend → "Sending…"), `email-actions.tsx` (`pending` → "Please wait…"), `account-dashboard.tsx` (`busy` disables action buttons) | Every async action disables its controls and changes its label. No double-submit path found (submit handlers early-return on `pending`). Minor note: the dashboard uses one shared `busy` flag, so one slow action disables unrelated buttons (e.g. Refresh while a delete is in flight) — cosmetic, no fix made. |
