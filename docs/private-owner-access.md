# Private owner access

The owner requested a working login on the live AmirNazir/AE-NUREL deployment before creating MySQL. The temporary server database is Node's built-in SQLite, kept in `.aenural-local/owner/` outside public assets, Git and deployment tracing. It stores actual hashed credentials, sessions, anonymous usage totals and the owner's caption projects. This is not a simulated login.

In production, when full MySQL membership is not enabled, the private owner mode is active by default. `AENURAL_OWNER_TEST_MODE=0` disables that fallback. Existing development accounts are unchanged unless owner mode is explicitly selected. This setup requires Node 22.13+ or 24 and a writable private directory. Use `AENURAL_OWNER_DATA_DIR` for a persistent Hostinger directory outside the deployment checkout if application redeployments replace the checkout. A single writable SQLite database is intended for this temporary, single-instance setup; migrate to the prepared MySQL integration for durable public accounts or multiple app instances.

Only one owner can be activated. Public registration and account deletion are disabled in this mode; no email service is needed to sign in. A random 256-bit activation token authorizes a one-time HTTPS POST to `/api/membership/activate-owner`. Only its one-way SHA-256 verifier and the owner email are in source. The token and generated password stay in the ignored local `.aenural-local/owner-credentials.json` file. No default password, plaintext credential, live session or database is committed. Once the owner exists, activation returns 410 and cannot overwrite the password. Password changes use the existing authenticated account settings flow; email recovery is not available without an email service.

Authenticated owner access comes from the verified server session and provisioned owner identity. It unlocks all 30 presets, advanced typography/animations, Accurate recognition and watermark-free export, within the existing two-minute/200 MiB/1080p safety limits. It does not create a fake payment or grant a customer Source Window license.

Signed-out visitors get five Free presets, Fast recognition, a 60-second video limit, watermarked video exports and three generation starts per UTC day. Locked presets, fonts and advanced controls remain visible. A signed HttpOnly first-party cookie identifies an anonymous browser; counts, retry reuse and concurrent-start limits live in SQLite. Anonymous limits are **per browser**, not a verified per-person allowance: clearing cookies or switching browsers creates a new anonymous identity. Browser-local rendering also remains modifiable by a determined visitor; this is not DRM. Genuine account-based enforcement uses the existing verified-account/MySQL path once configured.

Activation and signin are verified against a local production build before pushing. The live account is not reported active until HTTPS activation and a real login succeed on aenural.com. Hostinger must finish deploying the new commit; deployment/storage errors must be fixed rather than inventing a successful account.

## Activation and access checks

The ignored `.aenural-local/owner-credentials.json` contains `email`, `password` and `activationToken`. Keep this file private and preserve it separately from Git. If the original activation proof is lost, rotate its verifier in `owner-bootstrap.json` and securely retain the new token before deploying. Rotation permits initial activation only; an existing owner still returns 410 and cannot be overwritten.

Run `node scripts/membership/verify-owner.mjs activate https://aenural.com` after deployment to activate the owner and verify real sign-in, server-issued premium access, Free visitor restrictions, disabled registration and session revocation. Later checks use `verify` instead of `activate`. Both commands read secrets from the ignored file, print only sanitized results and sign out their QA session. For isolated local production QA, use a separate `AENURAL_OWNER_DATA_DIR` and `BETTER_AUTH_URL=https://aenural.com`, then run `node scripts/membership/verify-owner.mjs activate http://127.0.0.1:3118 https://aenural.com`. The client sends the configured public Origin header and manually carries the secure session cookie only to this explicit loopback server.
